# RunGrid v0.1.0

The first release of RunGrid schedules trusted Python workloads across concurrent
workers with durable PostgreSQL state and S3-compatible artifacts.

- Go REST API and CLI; Python SDK and gRPC workers.
- Resource-aware FIFO placement, heartbeats, leases, retries, and cancellation.
- At-least-once execution with fenced, idempotent result commitment.
- Checkpoint recovery, checksum verification, and append-only attempt history.
- Docker Compose demo, Prometheus metrics, and OpenTelemetry traces.
- Database/concurrency/race tests and seven end-to-end fault scenarios.

## Measured evidence

The repository includes raw results and reproduction scripts for 1–16 worker scaling,
three worker-kill/restart recovery trials, and 10K/100K queue-pressure cases. These
measurements come from a single Docker Desktop host, not a multi-machine cluster.

The real-data HeteroSplit demonstration completed 80 jobs using the original study's
eight dataset/regime combinations, two models, and five seeds. The proposed 160-job
grid requires additional valid regime definitions. Reduced training epochs demonstrate
scheduling and do not reproduce the published research accuracy.

See the [evidence and limitations](https://github.com/ZubairQazi/rungrid/blob/main/docs/evidence.md)
and [quickstart](https://github.com/ZubairQazi/rungrid#launch).

## Downloads

Linux and macOS binaries are available for amd64 and arm64. Each archive contains
`server`, `rungrid`, the README, and license. Verify downloads against `SHA256SUMS`.

RunGrid v0.1 is for trusted workloads on dedicated workers. It does not provide
authentication, untrusted-code isolation, GPU device assignment, or exactly-once execution.
